1) Product overview
-------------------
WBCode is a modern, gamified CS learning platform (EdTech) with:
- Interactive CodeLab (Monaco editor, run/submit code, sandbox execution).
- Quizzes (timed, multiple question types) + quiz tracks/hub.
- Roadmap learning path with module gating + Final Boss battles.
- Gamification: XP, levels, streaks, badges (large system), leaderboard seasons, WBC Coins.
- Social: friends, 1v1 challenges, chat (direct + support).
- Classes: professor creates class, students join via invitation code, announcements + assignments, local per-class leaderboard UI, assignment submission and approvals.
- Admin suite: user management, approvals, support tickets, admin messaging, analytics, dev tools.


2) Tech stack
-------------
Backend:
- NestJS (TypeScript)
- Prisma ORM
- MySQL
- JWT authentication (access + refresh)
- Security middleware: Helmet, CORS
- Scheduling: @nestjs/schedule (cron tasks)
- Rate limiting: @nestjs/throttler
- Sandbox integration: executes C/C++/Python via a separate worker

Frontend:
- Vite + React + TypeScript
- TailwindCSS + design system (dark-first, “pro SaaS” feel)
- React Router (role-aware routes + redirects)
- TanStack Query (React Query) for caching/mutations
- Zustand for auth/session store
- Monaco Editor
- Vitest + React Testing Library (component tests)

Sandbox Worker:
- Node worker executing code securely (C/C++/Python)
- Backend dispatches execution requests and validates results

4) Roles and permissions
------------------------
Roles:
- STUDENT
- PROFESSOR
- ADMIN

Authorization:
- JWT access token is attached via axios interceptor in frontend (`Authorization: Bearer <token>`).
- RolesGuard checks required roles (now normalized to uppercase and throws an explicit Forbidden message).
- Many endpoints are protected by JwtAuthGuard + RolesGuard.

Important nuance:
- `/coding` listing is role-sensitive:
  - STUDENT: only roadmap module categories (6 modules), excludes boss categories.
  - PROFESSOR/ADMIN: broader list (includes “legacy/custom/edu” categories, excluding boss).

6) Key systems & features (by role)
-----------------------------------

6.1 Student features
- Authentication flows:
  - Register/Login (JWT access + refresh)
  - Token refresh on 401
  - Forgot password + Reset password

- Student Dashboard:
  - XP, level, streak, rank
  - Stats and charts (progress, activity)

- CodeLab:
  - Exercise list with filters (search, difficulty, solved/unsolved)
  - Monaco editor: C / C++ / Python, syntax highlighting, formatting support
  - Run/Submit:
    - Sends code + optional stdin
    - Displays stdout/stderr
    - Success/Failure screen + feedback
  - Anti-copy detection:
    - Typing speed thresholds
    - Large paste detection
    - Score penalty for suspicious patterns
  - Hint system:
    - “Get Hint” endpoint
    - Custom hint (exercise.hint) or generated hint
    - (Platform concept) can cost WBC Coins depending on implementation
  - Activity events:
    - CODELAB_START analytics event (per exercise per session)

- Roadmap:
  - 6 modules: procedural-programming, object-oriented, data-structures, algorithms-logic, databases-sql, software-architecture
  - Gating: LOCKED / ACTIVE / COMPLETED based on exercises + boss completion set
  - Navigation to CodeLab via `?category=moduleSlug`

- Boss Battles:
  - Fetch tests for a moduleSlug
  - Complete and record boss completion when passed

- Quizzes:
  - Quiz hub + tracks + quiz runner
  - Timed quiz play
  - Submit answers, get score + feedback/explanations

- Missions:
  - View missions
  - Update progress (mission solve flows)
  - Claim rewards (XP/coins)
  - Analytics events: MISSIONS_VIEW, MISSION_CLAIM

- Challenges (1v1):
  - Create a challenge against another user (often friend)
  - Accept challenge
  - Solve via coding submit + challenge submit endpoint
  - Tracks challenge stats for badges and XP bonuses

- Friends:
  - Add friend (often from leaderboard)
  - List friends

- Chat:
  - Direct conversations
  - Support conversation
  - Polling-based “real-time” (2s poll interval)

- Classes:
  - Join class via invitation code
  - View joined classes list
  - Class dashboard:
    - Announcements
    - Assignments
    - Local per-class leaderboard computed from class members’ XP/levels
    - Assignment submission

- Profile & customization:
  - Profile page: XP, level, badges, submissions history
  - Edit profile fields (avatar/title/bio)
  - Cosmetics shop + equip/unequip

7) Learning-science / “science-based” mechanics (implemented)
-------------------------------------------------------------
These are the “science-informed” loops present in the product:

Immediate feedback loops:
- Coding autograding via sandbox + testCases/output validation
- Quiz autograding + explanations per question
- Failure/Success screens and contextual guidance

Operant conditioning / reinforcement:
- XP rewards for successful completion
- Visible progress bars and level-ups
- Badge unlock events + toast notifications

Habit formation:
- Streak tracking (daily consistency)
- Streak bonus logic (backend)
- Scheduled resets/rollups via cron

Goal-setting & commitment devices:
- Weekly missions with progress tracking and reward claiming
- Mission types cover multiple activities (coding/quizzes/active days/etc.)

Social learning / competition:
- Friends system
- Challenges 1v1 (competition + social proof)
- Leaderboard (top 50) with seasonal structure
- Local per-class leaderboard (within class)

Engagement analytics (data-informed iteration):
- ActivityEvent tracking (APP_OPEN, MISSIONS_VIEW, MISSION_CLAIM, CODELAB_START)
- Metrics aggregation (DAU, completion rate, etc.)

Anti-cheating / integrity:
- Suspicious typing detection (speed/paste thresholds)
- Score penalty for suspicious patterns (even when correct)

12) Known gotchas / development notes
-------------------------------------
- Role normalization:
  - JWT payload role can come as string or object; controllers normalize role to uppercase.
  - `/coding` behavior depends on correct role; if role is misread you’ll see only roadmap categories.

- Code validation:
  - Prefer explicit `testCases` in DB for robust grading.
  - If no testCases/examples, “smart validation” tries to infer expected output for some common problems; otherwise it rejects.

- Chat:
  - Uses polling (2s) rather than websockets; keep an eye on load/rate limiting.

- Prisma on Windows:
  - Occasional EPERM rename issues if node processes keep prisma binaries open. Stop dev servers and rerun generate/migrate.

- Cache invalidation:
  - After mutations (cosmetics purchase/equip, claim rewards, admin grant-all, etc.) invalidate relevant React Query keys.
